# Screenshot Annotator

[简体中文](README.zh-CN.md) · [Skill instructions](SKILL.md)

**Turn screenshots into clear action guides, with readable labels, ordered steps and review files you can check before sharing.**

A screenshot often leaves a beginner asking “where should I click?” This package adds an explicit action, keeps important text visible, and assembles several images in the order a person actually follows. It includes an AI-agent Skill and local Python tools. The tools work without an AI API key; understanding a real screen and confirming the result still requires a person or an agent capable of viewing images.

## Capability list

| Capability | Details and boundary |
|---|---|
| Single-image compatibility | v1 red rounded rectangles and numbered badges |
| Versioned batches | Stable asset IDs, explicit order, semantic filenames, preserved source copies and version directories |
| Coordinate grid | 100-pixel grid helps locate regions; it does not auto-detect intent or snap boxes |
| Action labels | v2 orange or red rounded frames, large labels, connected placement |
| Semantic markers | No redundant number for a single point; numbers for sequence; letters for alternatives |
| Protected regions | Prevent labels/markers from obscuring declared essential text and controls; callers must supply the regions |
| Scene contracts | Define what a button, row, navigation item or file result must include/exclude |
| Layout | Vertical sheets, 4–7-column grids and splitting under pixel/readability budgets |
| QA | Bounds, collisions, source hashes, image metadata, allowed pixel changes and consistency checks |
| Human review | Templates and append-only decisions bound to the version's manifest |
| Privacy inheritance | Consumes a verified upstream redaction audit when required; does not identify or redact personal data automatically |
| Revision workflow | Preserve previous versions and their review records; changed images require a new review |

## When to use it

| Your task | What you can prepare |
|---|---|
| Explain a product to a new colleague | Highlight the full control and write a short action label |
| Write a multi-screen tutorial | Declare the order, annotate each screen and create reading sheets |
| Explain two alternative entrances | Use A/B labels instead of implying a sequence |
| Review a large screenshot folder | Generate grids, local crops and reports for checking |
| Repair one inaccurate annotation | Produce a new version while preserving originals and earlier reviews |

## Try the synthetic demo first

Use an existing Python environment with Pillow, or create an isolated environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 examples/run_demo.py
```

The demo creates `demo-output/raw/settings.png`, its plan, and a version under `demo-output/output/synthetic-demo/versions/v001/`. Open `annotated/settings-annotated.png`, `overview/` and the QA crops. Run it again to create a new version. Existing versions are preserved.

```bash
python3 scripts/validate_annotation_project.py \
  --version-dir demo-output/output/synthetic-demo/versions/v001
```

A clean automatic report normally says `awaiting_manual_review`. This means the geometry and file checks succeeded; you still need to look at the actual images. The validator can only return final `passed` after a complete, version-bound manual review. See [review instructions](references/qa-review-v2.md).

## Use it with your AI agent

Place the complete repository in a directory your agent uses for Skills, with the folder name `screenshot-annotator`. Folder discovery differs between agents; do not copy only `SKILL.md`, because it needs the neighboring scripts and references. If your host does not discover Skills, give it `SKILL.md` and the repository location as task context.

Example request:

> Use screenshot-annotator to turn these safe demo screenshots into a tutorial. Preserve the original files. First propose the flow order and action labels, then render v2 annotations. Show the individual images, crops and overview for review. Do not mark the job as manually approved before I review it.

The Skill instructions and shipped v2 action-label validation currently use Simplified Chinese. English documentation explains the tool, but arbitrary English action labels are not guaranteed to pass the current copy checks.

## Make your own plan

1. Copy screenshots into a private working folder. If they contain personal or confidential information, first create and verify safe copies.
2. Use `examples/run_demo.py` as a complete runnable starting point or adapt [the batch manifest](examples/batch-plan-v2.json). The latter references images you must provide; it is a schema example, not a ready-made dataset.
3. Set `flow.order`, source files, target rectangles, protected text regions and action labels. Coordinates refer to the full source image in pixels, after any authorized crop.
4. Run the generator and independent validator, then inspect the output.

```bash
python3 scripts/annotate_batch.py --manifest my-plan.json --output-root output
```

For an existing v1 plan with numbered circular badges:

```bash
python3 scripts/annotate_screenshot.py \
  --input source.png --plan examples/annotation-plan.json \
  --output annotated.png --qa-dir qa
```

Adapt that example's rectangles to your own image before running it. v1 retains the classic red style; v2 provides richer batch and review behavior.

## What is in the repository

`SKILL.md` guides the agent. `scripts/` contains rendering and validation tools. `references/` documents contracts and review rules. `examples/` contains plans and the runnable synthetic demo. `tests/` contains synthetic regression tests. `data/annotation-style.yaml` holds configurable style defaults; public branding and local history start empty.

## Common questions

**Do I need to know Python?** You need to run a few terminal commands for the standalone tools. An agent with local file and shell access can run them for you; it must still inspect the images.

**Will it discover every button automatically?** No. The target suggestion helper is limited to documented scene templates. You or your agent must confirm the target rectangle and the real operation order.

**Why did rendering stop with a collision?** The proposed label overlaps protected content or another annotation. Move its anchor, shorten the label, split the image or correct the protected region. Do not erase a real protection merely to obtain a passing report.

**Can I share the QA folder?** QA images, source copies, crops and manifests can reveal the same information as the screenshots, including runtime source paths. Keep the whole output private until you check it. The repository demo uses only invented data.

**Does it blur personal information?** No. The Skill describes an optional `image-sharing-redaction` companion, which is not bundled here. You must provide verified safe copies and the required audit for sensitive jobs. The no-sensitive-data demo needs no companion.

**Can it remove a watermark?** Unknown or copyright-related marks remain. Only authorized, deterministic changes on a work copy are eligible under the documented contract; complex generative removal is outside this package.

**Which file types work?** PNG, JPEG and single-frame WebP enter the deterministic batch workflow. PDF, video, SVG and animated images require other tools or are archived as unsupported.

**Why are Chinese labels missing on my computer?** A font that covers those characters must be available. The code tries system font candidates. Check your font coverage and validate rendered text; Linux and Windows font availability varies.

**Is a successful command enough to publish?** No. Check full images, crops and final overview. Automated checks cannot prove that the box teaches the correct action.

## Validation and limitations

Run the regression suite with `python3 -m unittest discover -s tests -t .`. See [the release validation record](docs/validation.md) for actual results. The code depends on Python and Pillow; there is no network service, account login or bundled API credential. Automated OCR discovery is not included. Screenshots, personal data and third-party logos supplied by a user remain the user's responsibility.
