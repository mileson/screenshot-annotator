# 动作标签与编号

## 核心原则

标签先告诉普通用户“要做什么”或“会看到什么”，再由目标框回答“在哪里”。不要把控件对象名、内部实现名、资产编号或页码当成标签。

动作标签使用大号简体中文。能用短句说清时保持一行；需要补充对象时使用“动作 + 必要对象”，不要堆入原因、条件和教程正文。

`action-orange-v2` 与 `action-red-v2` 在参考宽度 1179 px 时都使用 44 px 基准字号，并以 44 px 作为该参考宽度下限。窄图可以按宽度缩放，绝对最小字号为 24 px。字号和标签宽度都可配置；不得把 44 px 硬套到任意小画布，缩放后仍须满足人工可读性。

## 页面类型与词表

### 操作页

操作页只使用以下动作开头：

- `点击`
- `选择`
- `填写`
- `上传`
- `阅读`
- `核对`
- `查看并确认`

合格示例：

- `点击保存`
- `选择深色模式`
- `填写显示名称`
- `上传示例图片`
- `阅读权限说明`
- `核对通知范围`
- `查看并确认更改`

不合格示例：

- `保存按钮`：只写了对象，没有动作。
- `通知设置`：只写了区域名称。
- `进入下一页`：描述了内部页面跳转，没有说明用户动作。
- `第 3 页`：生产页码不是用户操作。

对象名可以跟在动作后面，但不能替代动作。例如 `点击保存按钮` 可以使用，`保存按钮` 不可以。

### 信息页

信息页允许以下形式：

- `阅读 + 内容`
- `核对 + 状态或数值`
- `结果：+ 用户可见结果`

合格示例：

- `阅读使用说明`
- `核对当前状态`
- `结果：设置已保存`

信息页没有真实操作时，不要为了统一格式虚构“点击”。

## 编号决策

| `semantic_role` | 默认标记 | 使用条件 |
| --- | --- | --- |
| `single` | 无 | 独立教学点，不属于连续步骤或互斥入口。 |
| `sequence` | 数字 | 用户必须按真实先后顺序完成。 |
| `alternative` | `A`、`B` | 用户只需选择其中一个互斥入口。 |

单张图只有一个独立标注时，默认免编号。若该标注属于跨页面的真实连续流程，应使用 `sequence` 并保留数字；“单标注免编号”不能抹掉真实顺序。

数字只表示操作顺序，不表示页码、截图序号、文件序号或跳转编号。不要把 `1`、`2` 再写进标签文本。

`A`、`B` 只用于互斥入口。并列但需要全部完成的操作仍属于数字顺序；普通信息对比不应为了视觉对称强行使用 `A`、`B`。

## 编号作用域

`flow.numbering_scope` 决定计数器在哪里重置：

- `job`：默认值，整套任务共用一个数字计数器和一个字母计数器，兼容旧项目
- `section`：每个 `section_id` 独立从 `1` 和 `A` 开始，适合公众号每个部分重新编号的教程

使用 `section` 时，每张资产都必须提供非空 `section_id`。引擎根据 `flow.order` 遍历素材，在同一章节内继续计数，进入另一个章节时使用该章节自己的计数器。验证器会独立重算，缺少章节 ID、出现跳号或跨章节串号都应阻断。

## 自动与手动标记

- `callout.marker: auto`：由 `semantic_role` 决定无标记、数字或字母。
- `single` 只允许 `auto/none`。
- `sequence` 只允许 `auto/number`。
- `alternative` 只允许 `auto/letter`。

Marker 是语义结果，不是自由装饰。自定义文字、`single + number`、`sequence + letter`、`alternative + none/number` 都必须阻断，不能靠手动配置绕过单点免编号或 A/B 规则。

## 交付前检查

- 标签是否以允许的动作或结果形式开头。
- 用户是否能同时看懂“做什么”和“在哪里”。
- 是否存在只写对象名的标签。
- 是否把页码、资产编号或跳转编号写进图内。
- 数字是否对应真实顺序。
- 需要分章节编号时，是否显式设置 `numbering_scope: section`，且每张图都有正确的 `section_id`。
- `A`、`B` 是否确实互斥。
- 独立单标注是否无多余编号。
