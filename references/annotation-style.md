# v1 兼容标注样式规范

本文件保留 `classic-red-v1` 的单图兼容规则。新建批量教程项目优先使用 v2，并同时阅读：

- `callout-copy-and-numbering.md`
- `alignment-and-collision.md`
- `sequence-and-board-layout.md`
- `qa-review-v2.md`

不要把本文件的“红框 + 圆形编号”默认值强行套到 v2。v2 可显式选择 `action-orange-v2` 或 `action-red-v2`，并通过文字标签、数字、字母或无标记表达不同流程语义。

## 坐标

- 坐标使用原始截图像素，不要使用缩放后的预览图坐标。
- 不要把浏览器 DOM 坐标、CSS 像素、无障碍树坐标或裁切图坐标直接当成最终截图坐标；先确认它们和原始截图像素的缩放关系。
- 如果截图经过 Retina 缩放、窗口缩放、浏览器缩放或二次裁切，先用原始图尺寸和目标区域实际像素位置复核，再写入计划 JSON。
- 矩形使用 `[x1, y1, x2, y2]`。
- 编号圆点使用圆心 `[x, y]`。
- 红框应给目标 UI 留出少量边距，不要让红色线条压进目标内容。
- 坐标不确定时，先做小范围试标注并查看 QA 裁切图；不要在整套图上批量沿用未经验证的偏移量。

## 框选区域

- 红框框选用户视觉上会理解为“一个功能区”的完整区域，而不是只框住标题、图标、按钮文字或内部局部。
- 卡片、表格、图表、设置项、状态栏和列表行通常按完整组件边界框选，并保留 8-18 px 左右的视觉边距。
- 红框不要切断组件圆角、分割线、坐标轴、表头、状态徽标或按钮边界。
- 当目标区域很大时，优先框关键子区域；如果整屏都要解释，拆成多张图或减少标注密度。
- 相邻框之间至少留出能被肉眼区分的空隙；如果两个区域贴得太近，考虑合并为一个教学点或换截图范围。

## `classic-red-v1` 默认视觉样式

- 红色：`#E62323`
- 数字：白色
- 高分辨率桌面截图线宽：7 px
- 圆角半径：14 px
- 编号圆半径：28 px

超高分辨率截图可适当加粗线条和编号圆；紧凑移动端截图可适当缩小。

`data/annotation-style.yaml` 是 Skill 规划与维护时读取的人类可读偏好表；每个 v2 作业仍必须在 Manifest 中显式选择 preset，引擎再把完整解析值固化到产物。两者通过测试防止漂移。橙色是默认但可选的新版预设；需要新版能力和红色视觉时使用 `action-red-v2`，不能直接改写旧计划的红色视觉基线。

## 编号位置

- 编号放在用户阅读路径的起点附近。
- 能放在目标框外侧时，优先放外侧。
- 教程文档场景中，编号圆不要贴着红框边线；外侧留白不足时，先调整红框或换截图，不要让编号和框线产生交叉感。
- 不要遮挡用户必须识别的文字、按钮、菜单项或控件。
- 不要遮挡图表折线、柱状条、坐标轴、图例、状态徽标、价格/Token 数字、错误提示和主要 CTA。
- 多个编号尽量沿阅读顺序摆放，避免编号之间互相贴近、斜跨目标区域或形成视觉交叉。
- 编号与红框边线之间应有明显间隔；如果编号只能放在框内，放在没有文字和关键数据的空白角落。
- 脚本会用 `ImageDraw.textbbox()` 计算数字真实边界，并处理字体 bbox 的 left/top 偏移，让数字在圆内居中。

## QA 检查清单

- 红框位置和目标 UI 一致，没有明显偏移。
- 坐标基准正确，没有因为缩放、裁切、Retina 或窗口尺寸变化导致整体偏移。
- 红框框住完整视觉区域，没有切断组件边界，也没有把无关区域大面积框入。
- 红框四周边距均衡。
- 相邻红框之间有清楚间距，没有共线、贴线或交叉感。
- 数字在红色圆内上下左右居中。
- 编号圆不遮挡关键内容。
- 报表或图表截图中，编号不遮挡趋势、分类、Top 项、数值、图例或异常/空态提示。
- 红色线条在截图背景上清楚可见。
- 已打开并检查 QA 文件夹里的裁切图和 `qa-contact-sheet.png`。
- 多张教程图交付时，额外检查整套图的 `full-annotated-contact-sheet.png`。
- `review.json` 中不能留下未处理的 blocker。

## 拒绝交付的情况

- 红框框错区域，或只框住目标的一部分。
- 编号圆明显偏上、偏下、偏左或偏右。
- 标注挡住用户要点击或阅读的内容。
- 编号圆贴线、红框共线或红框压住按钮文字。
- 多个标注交叉、拥挤或让用户分不清编号对应哪个区域。
- 裁切图看不出标注和目标之间的关系。
- 只看脚本输出，没有做人工视觉复核。
